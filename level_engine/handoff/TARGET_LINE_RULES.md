# 目標線段規則（2026-10-05）

此補充文件適用於完整關卡 JSON，供 App 與影像辨識／關卡運算端接手。

## 必須同時滿足的條件

畫出的目標線段是必要條件。子球黃色線段由本桿目標子球完成，母球白色線段由母球完成。每桿需碰到該球種所有適用線段，順序不限；同一條碰多次只算一次。線段上的編號用於辨識，不表示順序。其他子球不能代替目標子球完成。

成功 = 原本的進袋／停區／留桌條件成立 AND 所有必要線段已接觸 AND 沒有犯規。
「進袋或區塊」仍是二擇一，但線段條件必須另外完成。沒有線段時不增加條件。

## JSON

- 幾何：`diagram.lines[]`，每筆含 `x1,y1,x2,y2,side,shot`。
- 座標：整張球桌圖片的 0–1 比例座標，轉星座標使用 `setup.coordinateSystem.imageBounds`；不可直接把 x、y 比例當作等距單位。
- 規則：`objectRules.lineRequirement`、`cueRules.lineRequirement`。
- E 模板逐桿：`shotRules.first.object/cue.lineRequirement` 和 `shotRules.second.object/cue.lineRequirement`。

```json
{
  "required": true,
  "lineIndexes": [0],
  "match": "all",
  "order": "any",
  "event": "ball_body_touches_segment",
  "scope": "current_shot",
  "combineWithTarget": "and"
}
```

`lineIndexes` 是 `diagram.lines` 的零起算索引。E 模板只檢查當前桿次，舊線段未帶 shot 時適用兩桿。其他模板每次擊球均檢查同球種線段。刪除線段後匯出會重新計算索引。
舊 JSON 若有 diagram.lines 但沒有 lineRequirement，依相同球種／桿次規則建立必要條件；不能當作純裝飾。遇到未知規則不得靜默略過並判成功。

## 接觸判定

使用真實球體接觸線段，不要求球心穿越。將桌面校正成等距座標後，球心到有限線段（包含端點）的最短距離 <= 真實球半徑 + 辨識容差，即為接觸。不要使用畫面上「放大 1.3 倍」的顯示半徑，也不要以線條粗細擴大判定範圍。

應以相鄰可靠影格間球心軌跡形成的掃掠圓盤檢查，避免快速移動漏判。遮擋或追蹤斷裂時不得用長直線補接推定接觸；回傳不確定並等待補證或人工確認。接觸旗標只在擊球開始至全部球靜止之間累積，每一桿開始歸零；擺球移動與球仍未運動時不算完成。

## 第 3、4 關

- 第 3 關：直接擊打子球，碰到上庫黃色線段後，停在下方目標區塊。線段位於星座標 (5.5,0) 至 (6.5,0)。
- 第 4 關：直接擊打子球，碰到左庫黃色線段後，停在右方目標區塊。線段位於星座標 (0,1.5) 至 (0,2.5)。

線段位置依既有反彈路線與目標區塊寬度補齊。兩關均每次判定後重擺，10 次中成功 8 次過關；8／9／10 次對應一／二／三星。只停進區塊、未碰線段不算成功。

工作台產出規則與教學動畫；真實球接觸事件需由 App 的影像辨識與規則引擎執行，動畫不可代替實際判定。

## 工作台可疊加標記

「＋ 經過目標線段」是必要接觸條件的畫線入口，標記「可疊加條件」。終點選項維持單選，線段可額外搭配。已畫線才顯示「已疊加 N 條」；僅點按工具但未畫線，不產生 lineRequirement.required=true。第一／第二桿與子／母球分開計數。使用者已確認「球體碰到線段即可」；不是球心穿越事件。
