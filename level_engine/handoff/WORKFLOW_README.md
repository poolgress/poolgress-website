# 新版關卡流程示範

入口：`dist/workflow/index.html`。使用 `poolgress.coach-level` version 1，從模板與球桌標記開始，接續擺球、擊球、判定及結算。

狀態（2026-10-05）：使用者指出流程有重大失誤並要求擱置；此預覽尚未驗收，不應直接作為正式 App 流程依據。

## 工作台內嵌預覽

`dist/editor/` 下方已加入目前關卡的流程預覽。工作台的球位、規則、名稱與教學說明會自動同步；修改設定後從模板與球桌標記重新開始。未通過檢查時暫停流程，顯示缺少的設定。「重新預覽」可以從頭開始。同步只在同源父頁與內嵌頁之間進行，沒有外部傳輸。

## 使用

從 `dist` 啟動靜態伺服器：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

開啟 `http://127.0.0.1:8765/workflow/`。亦可直接開啟 `dist/workflow/index.html`；本頁不需要 npm 安裝或建置。

- 選擇內建 20 關、貼上單關 JSON，或選擇 JSON 檔案。
- 題庫可使用關卡陣列，或 `{ "levels": [...] }`。匯入題庫後可透過「重新開始」選擇其他關卡。
- 所有關卡在本機處理，不會上傳至網站或連接實體球桌。
- 判定頁手動回報子球與母球是否符合指定終點、必要線段是否接觸、順序及犯規。
- 母球停球區條件額外核對輸入的星座標；D/E 續桿保留母球輸入座標與剩餘子球，不重擺。
- 任意順序清檯可選擇本桿目標球。
- 證據不足保留在判定階段，不記成功或失敗。

## 流程

A：每次一顆子球，判定後換下一次。
B：固定母球＋子球，每桿後重擺。
C：逐項使用 `setup.rounds`，不再乘 `cycles`。
D：成功原位續桿，失誤結束本局，清檯過關。
E：每輪兩顆子球，依 `shotRules.first/second` 判定；清完才記一輪成功。任一桿失敗結束本輪，達總輪数才結算。

線段按球種與 E 桿次套用，每桿重新勾選。舊 JSON 缺少 `lineRequirement` 時由 `diagram.lines` 補齊；矛盾或未知線段規則拒絕載入。E v1 若超過兩顆子球，目前拒絕載入，避免不明確的第三桿規則。

## 邊界

這是人工操作的流程驗證工具，沒有相機、球體追蹤或物理模擬。子球進袋、順序、其他球位移與碰線由操作者確認，不從教學路線推論成功。剩餘子球位置保持不動，前提是該桿沒有移動其他子球；實際 App 須用影像觀測更新全部球位。

`engine.js` 分開管理 runtime，不修改原始 JSON。App 可參考其 A–E 狀態切換，但真人逐桿觀測及幾何接觸運算應依既有 `VISION_AND_LEVEL_ENGINE_HANDOFF.md` 實作。

## 驗證與部署

```sh
node scripts/check-workflow.cjs
```

涵蓋全 20 關載入、五種模板完整結算、第 12 關八輪、重擺與續桿、第 20 關逐桿規則、缺少碰線失敗、證據不足、無效 JSON 拒絕。

部署需保留 `dist/workflow/`、`dist/editor/model.js`、`dist/editor/presets.js` 與 `dist/editor/assets/` 的相對路徑。可直接上傳整個 `dist`；正式網站使用 /level_engine/workflow/；原 /workflow/ 頁面保留。
